## 1 需求基线

### 1.1 功能需求

| 编号 | 需求 | 确认的行为 |
|---|---|---|
| R1 | 常驻与热键 | 常驻托盘。全局热键 **Ctrl+1** 截图、**Ctrl+2** 录 GIF，均可在配置中修改 |
| R2 | 划区域 | 按下热键后冻结屏幕，拖选区域。可以调整选区（拖手柄改大小、拖动整体、方向键微调），然后确认 |
| R3 | 截图编辑 | 调整选区时可以简单编辑：矩形、椭圆（圆）、箭头、画笔、文字、马赛克；可选颜色、线宽、字号；支持撤销与重做 |
| R4 | 截图输出 | 确认（Enter、双击或 ✓）= **复制到剪贴板**。工具条上的“保存”可以选择位置，保存为 PNG/JPG/BMP。不自动保存 |
| R5 | 参考图 | 按 Ctrl+1 选区并按需调整和编辑，点「贴图」钉在原位置。参考图支持双击收缩和还原 |
| R6 | 参考图管理 | 回收站、隐藏/显示全部、关闭全部、鼠标穿透、把剪贴板图片贴成参考图 |
| R7 | GIF 录制 | 按 Ctrl+2 选区后选择帧率，默认 **30 fps**。录满五分钟自动停止，也可再按 Ctrl+2 或点「停止」 |
| R8 | GIF 预览与保存 | 录完弹出预览窗口循环播放，支持点击和拖动进度条，显示尺寸、时长和文件大小。可以保存文件、复制 GIF 或放弃 |
| R9 | 配置 | exe 同目录下的一个 INI 文件，首次运行时自动生成，带中文注释，保存后立即生效 |

### 1.2 非功能需求

| 编号 | 指标 | 目标 |
|---|---|---|
| N1 | 便携性 | 只有 `VisPick.exe`，外加首次运行自动生成的 `VisPick.ini`。不用安装，不依赖运行库，不需要管理员权限，不写系统目录 |
| N2 | 兼容性 | Windows 7 SP1、8.1、10、11；32 位和 64 位系统；ARM 设备通过系统自带的模拟运行 |
| N3 | 体积 | 单个 exe ≤ 2 MB（预计约 1 MB） |
| N4 | 资源占用 | 空闲时 CPU 为 0%；没有参考图时内存 ≤ 10 MB |
| N5 | 响应速度 | 从按下热键到浮层出现：本机 2×4K ≤ 150 ms，1080p 单屏 ≤ 80 ms |
| N6 | 准确性 | 在多显示器、混合 DPI、坐标为负的布局下，截图和参考图都像素级准确 |
| N7 | 隐私 | 不联网，没有遥测。只写配置文件、用户选择的保存位置和临时目录 |

### 1.3 v1 不做

OCR、滚动长截图、MP4 录制与录音、GIF 剪辑、云上传、图形化设置界面、参考图在重启后恢复、修改已经画好的标注（只支持撤销和重做）。

## 2 技术方案

### 2.1 技术选型

**结论：用 C++20 直接调用 Win32 原生 API，用 Visual Studio 2022（MSVC v143 工具集）编译，静态链接 C 运行库，运行时不依赖任何第三方库。**

| 维度 | **C++ + Win32（选用）** | Rust + windows-rs |
|---|---|---|
| 支持 Windows 7 / 8.1 | ✅ VS2022 的 v143 工具集官方支持以 Win7/8/8.1 为目标（见[微软文档](https://learn.microsoft.com/en-us/cpp/overview/supported-platforms-visual-cpp?view=msvc-170)） | ⚠️ 只有 Tier-3 目标，需要用 nightly 自行编译标准库，不稳定（见 [rustc 文档](https://static.rust-lang.org/doc/stable/rustc/platform-support/win7-windows-msvc.html)） |
| 运行依赖 | 无：/MT 静态链接 CRT，只用系统自带的 DLL | 无（但仅限 Win10 及以上） |
| 32 位版本 | ✅ | ✅（仅 Win10 及以上） |
| exe 体积 | 约 1 MB | 约 2–3 MB |
| 本机工具链 | ✅ 已经具备：VS2022 17.12、MSVC 14.42、CMake 3.29、Ninja 1.12、AddressSanitizer | 需要另装 rustup |
| 内存安全 | 靠工程规范保证：RAII、不写裸 new/delete、/W4、/analyze、ASan | 由语言保证 |

决定性因素是“任何一台 Windows 设备都能用”。要覆盖仍在使用的 Win7/8.1 机器和 32 位系统，C++ 是唯一稳定的选择。

> ⚠️ **必须锁定工具集**：VS2026（18.0）及以后的版本已不再支持以 Win7/8/8.1 为目标。项目固定使用 VS2022 的 v143 工具集（当前为 14.42），构建脚本会校验工具集版本，防止误升级。

**用到的系统组件（全部随 Windows 自带）**

| 系统组件 | 用途 | Win7 是否可用 |
|---|---|---|
| user32 / gdi32 | 窗口、消息、热键、GDI 绘制、截屏（BitBlt） | ✅ |
| gdiplus | 抗锯齿绘制标注：线、矩形、椭圆、箭头、画笔 | ✅ |
| windowscodecs（WIC） | 编码 PNG/JPG/BMP；解码剪贴板和文件中的图片；解码 GIF 用于预览；高质量缩放 | ✅（在 Win7 上需使用 `CLSID_WICImagingFactory1`） |
| shell32 / ole32 | 托盘、文件对话框、系统已知文件夹、剪贴板文件列表 | ✅ |
| dwmapi | 获取精确的窗口边界、关闭窗口动画 | ✅（部分属性要 Win8+，有降级处理） |
| shcore（延迟加载） | 获取每台显示器各自的 DPI | Win8.1+；Win7 自动降级 |
| imm32 | 文字工具中输入法的定位 | ✅ |
| winmm | 旧系统上录屏所用的定时精度 | ✅ |
| advapi32 | 开机自启所需的注册表读写 | ✅ |
| dbghelp（动态加载） | 崩溃时写转储文件 | ✅ |

**第三方库：无。** GIF 编码器（LZW 压缩加颜色量化）和 INI 解析器都自己实现，各约 300–500 行，配完整的单元测试。单元测试框架用 doctest（单个头文件，MIT 许可证），只在开发时使用。

### 2.2 兼容性策略

**发布形态**：同一份源码构建出两个版本，每台机器只需要其中一个 exe。

| 文件 | 适用范围 | 说明 |
|---|---|---|
| `VisPick.exe`（x64） | 64 位 Windows 7 SP1 – 11；Win11 ARM 设备（模拟运行） | 推荐，性能和内存余量更好 |
| `VisPick-x86.exe`（32 位） | 所有 Windows 7 SP1 – 11，包括 32 位系统和所有 ARM 设备 | 通用兼容版，不确定设备情况时用它 |

ARM64 原生版本可选：需要在 VS 中加装 ARM64 生成工具。模拟运行已经够用，v1 不做。

**编译期约束**

- 定义 `_WIN32_WINNT=0x0601`（即 Win7），让 Win8 及以上才有的 API 在编译期就不可见。
- 新系统的 API 一律经过 `compat` 模块：运行时先探测是否存在，再调用（GetProcAddress 或延迟加载）。
- 构建脚本用 `dumpbin /imports` 检查静态导入表。只要出现 Win7 上不存在的导入，构建就失败。

**新旧系统的功能降级**

| 功能 | 新 API 及最低系统 | 旧系统上的做法 |
|---|---|---|
| 每台显示器独立 DPI | Per-Monitor V2（Win10 1703）；Per-Monitor（Win8.1） | Win7/8 使用系统 DPI 感知。Win7 本来就只有一个全局 DPI，内部坐标仍然是物理像素 |
| 录制框不出现在 GIF 中 | `WDA_EXCLUDEFROMCAPTURE`（Win10 2004） | 录制框画在选区外侧；选区接近全屏时自动隐藏工具条，改用 Ctrl+2 停止 |
| 高精度录屏定时 | 高精度可等待定时器（Win10 1803） | 用 `timeBeginPeriod(1)` 加普通定时器 |
| 精确的窗口边界 | `DWMWA_EXTENDED_FRAME_BOUNDS`（需开启桌面合成） | Win7 经典主题下改用 `GetWindowRect` |
| 跳过系统隐藏的窗口 | `DWMWA_CLOAKED`（Win8） | Win7 上没有这类窗口，不需要处理 |
| 高质量缩放 | WIC HighQualityCubic（Win10） | 用 WIC 的 Fant / Cubic 插值 |
| 界面字体 | Microsoft YaHei UI（Win8+） | 依次退回 Microsoft YaHei（Win7）、SimSun |

### 2.3 总体架构

```
VisPick.exe（单进程，同时只运行一个实例）
│
├─ UI 线程（唯一的消息循环，所有窗口都在这里）
│   ├─ MainWindow（隐藏的顶层窗口）：热键、托盘、命令行（WM_COPYDATA）、配置变更、后台任务回调
│   ├─ CaptureOverlay：冻结屏幕 + 选区 + 编辑工具条，三种模式共用
│   ├─ PinWindow × N：参考图
│   ├─ RecordFrame + RecordBar：GIF 录制框与工具条
│   ├─ GifPreviewWindow：GIF 预览与保存
│   └─ Osd：轻提示（如“已复制”），自动淡出
│
├─ ConfigWatcher 线程：监听配置文件的变化
├─ GIF 录制期间：采集线程（按所选帧率抓帧）→ 编码线程池（并行量化和 LZW 压缩）→ 写出线程（按帧序写文件）
└─ 一次性任务线程：保存图片（WIC 编码）等耗时 IO
```

原则：窗口和界面状态只属于 UI 线程。后台线程只做计算和 IO，通过 `PostMessage` 把结果交回 UI 线程。

**源码结构**

```
VisPick/
├─ CMakeLists.txt  CMakePresets.json  build.ps1
├─ res/       VisPick.ico  VisPick.manifest  VisPick.rc（版本信息）  default.ini（默认配置模板）
├─ src/
│  ├─ main.cpp  App.*          入口、单实例、全局状态、命令分发
│  ├─ core/     Config.*  Ini.*  Hotkey.*  Paths.*  Log.*  CrashDump.*
│  ├─ platform/ Compat.*（动态加载新 API）  Window.*（窗口基类与消息分发）  Gdi.*（句柄 RAII、DIB）
│  │            Dpi.*  Monitor.*  Tray.*  Clipboard.*  FileDialog.*  SingleInstance.*  Autostart.*  Notify.*
│  ├─ capture/  ScreenGrab.*  WindowSnap.*  Cursor.*
│  ├─ overlay/  CaptureOverlay.*  Selection.*  Magnifier.*  Toolbar.*  Icons.*（矢量图标）
│  ├─ editor/   Annotation.*（数据模型）  Tools.*  TextInput.*  Mosaic.*  Renderer.*  UndoStack.*
│  ├─ pin/      PinManager.*  PinWindow.*  PinRender.*  Compact.*
│  ├─ gif/      Recorder.*  CaptureThread.*  EncoderPool.*  Quantizer.*  Lzw.*  GifWriter.*  PreviewWindow.*
│  └─ imaging/  Bitmap.*  ImageOps.*（裁剪、旋转、翻转、马赛克）  Wic.*（编解码与缩放）
├─ tests/
│  ├─ unit/     单元测试（doctest）
│  └─ e2e/      VisPickTest.exe：自动化验收驱动（见 §5.3）
└─ docs/
```

**核心抽象**

- `Bitmap`：32 位 BGRA 像素缓冲，行与行之间没有填充。这是全项目统一的图像类型，可以和 GDI 的 DIB 互相转换。
- `Command`：热键、托盘、命令行和工具条按钮都转换成命令，统一交给 `App::Dispatch` 处理。
- `Window` 基类：封装窗口类注册和消息分发，派生类重写 `OnMessage`。所有 GDI/COM 句柄都用 RAII 包装，杜绝泄漏。
- 重入规则：弹出菜单、对话框等模态调用期间，系统会再次进入窗口过程。因此进入模态调用前不持有可变状态的引用，必要时用 `PostMessage` 推迟处理。

### 2.4 坐标与 DPI 模型

- manifest 中同时声明 `dpiAware=true/pm` 和 `dpiAwareness=PerMonitorV2,PerMonitor`，各版本系统会自动选用自己支持的最合适的一种。
- 所有几何量都使用**虚拟桌面的物理像素**，坐标可以为负。截屏、窗口识别、选区、参考图、录制区域都在同一个坐标系里，没有换算误差。
- 界面元素（字体、工具条、放大镜、边框、收缩方块）按所在显示器的 DPI 缩放：物理像素 = 逻辑值 × dpi / 96。
- 参考图在 100% 缩放时，图像的 1 个像素对应屏幕的 1 个物理像素。在 DPI 不同的显示器之间拖动时，像素尺寸保持不变。

### 2.5 关键模块设计

#### 2.5.1 常驻框架

- **单实例**：用命名互斥量判断。重复启动时，把命令行参数通过 `WM_COPYDATA` 转给已经运行的实例，然后退出。
- **热键**：用 `RegisterHotKey`（加 `MOD_NOREPEAT`）注册，默认 Ctrl+1/2。注册失败的热键在托盘通知和「关于」中列出。键位被占用时，每两秒重试一次，成功后停止重试。
- **同一热键在不同状态下的含义**：
  - 空闲时：进入对应模式；
  - 浮层已打开时按另一个模式的热键：切换到该模式；
  - 录制 GIF 时按 Ctrl+2：停止录制。
- **托盘**：
  - 左键单击 = 截图。
  - 右键菜单：截图、录制 GIF、截取参考图、从剪贴板贴图、参考图子菜单（显示/隐藏全部、关闭全部、取消全部穿透、恢复最近关闭）、打开配置文件、重新加载配置、开机自启、关于、退出。
  - 监听 `TaskbarCreated` 消息，资源管理器重启后自动恢复托盘图标。
- **命令行**：`--screenshot | --gif | --pin | --pin-clipboard | --pin-file <路径> | --toggle-pins | --reload | --exit`，以及 `--config <路径>`。
- **首次启动提示**：托盘气泡说明 Ctrl+1 截图后可贴图、复制或保存，Ctrl+2 录制 GIF。
- **退出**：如果还有参考图或未保存的 GIF 预览，先请用户确认。
- **开机自启**：托盘开关写入 `HKCU\...\Run`，不需要管理员权限。仅在已登记的同名程序路径确定不存在时修复，并保留原有显式配置参数。

#### 2.5.2 划区域浮层（三种模式共用）

**流程**

1. 按下热键后，用 `BitBlt(SRCCOPY|CAPTUREBLT)` 抓取整个虚拟桌面，同时记录当前的窗口列表。
2. 显示预先创建好的全屏置顶浮层（已关闭显示动画）。
   - 若 Windows 拒绝自动激活，浮层最多等待 8 秒。用户可拖动激活并选区，或右键关闭。切到另一应用会关闭浮层。
3. 用户选区，然后调整、编辑。
4. 确认后按当前模式输出。

**状态机**

```
 热键 ─▶ 选择中（鼠标悬停处的窗口高亮）
            │ 拖动画框 / 单击选中窗口
            ▼
         已选区（显示手柄和工具条）◀────────────────┐
            │ 拖手柄改大小 · 拖内部移动 · 方向键微调      │
            │ 选中某个工具后，在选区内绘制标注 ──────────┘
            ├─ Enter / 双击选区 / ✓ ──▶ 执行该模式的默认动作，关闭浮层
            ├─ 工具条上的其他动作（复制 / 保存 / 钉住）──▶ 执行后关闭浮层
            ├─ 右键 ──▶ 选中了工具时：取消该工具；没有标注时：清除选区，回到“选择中”；没有选区时：退出
            └─ Esc ──▶ 放弃，关闭浮层（正在输入文字时，Esc 只结束文字输入）
```

**三种模式的差异**

| 模式 | 选框颜色 | 工具条 | Enter / 双击 / ✓ 的动作 |
|---|---|---|---|
| Ctrl+1 截图 | 蓝 | 编辑工具、保存、贴图、取消、**✓ 复制** | 复制到剪贴板 |
| 托盘「参考图」或 `--pin` | 绿 | 编辑工具、保存、复制、取消、**✓ 钉住** | 钉到屏幕的原位置 |
| Ctrl+2 GIF | 红 | 帧率选择、**● 开始录制**、取消 | 开始录制 |

**工具条布局**：默认放在选区右下方的外侧；下方空间不够时放到上方，再不够就放在选区内侧。

```
 [矩形][椭圆][箭头][画笔][文字][马赛克] | [保存][钉住][取消][✓ 复制]
 ■ ■ ■ ■ ■ ■ ■ ■ | 细 中 粗 | 小 中 大          ← 选中某个工具后才出现的属性栏
```

**绘制**：用 GDI 双缓冲，只重绘发生变化的区域（脏矩形）。进入浮层时先预计算一张压暗图，标注层用 GDI+ 抗锯齿绘制。

**选择辅助**

- 放大镜：把光标周围 15×15 像素放大 8 倍，并显示坐标和颜色值。
- 尺寸标签：显示选区的宽和高。
- 窗口自动识别：单击选中整个窗口；在桌面上单击，选中整台显示器。
- 方向键微调：每次 1 px，按住 Shift 为 10 px。
- 小于 4×4 像素的选区视为单击。

#### 2.5.3 截图编辑器

| 工具 | 快捷键 | 说明 |
|---|---|---|
| 矩形 | R | 空心矩形；按住 Shift 画正方形 |
| 椭圆 | E | 空心椭圆；按住 Shift 画正圆 |
| 箭头 | A | 带箭头的直线；按住 Shift 以 45° 吸附 |
| 画笔 | P | 自由曲线，自动平滑 |
| 文字 | T | 单击放置输入框，支持中文输入法和多行；点击别处或按 Esc 完成 |
| 马赛克 | M | 拖出一个矩形区域打码 |

- **属性栏**：8 种预设颜色；线宽细、中、粗（2/4/6 逻辑像素）；字号小、中、大（14/20/28 逻辑像素）。
- **撤销/重做**：Ctrl+Z 和 Ctrl+Y，至少 50 步。
- **其他快捷键**：Ctrl+C 复制，Ctrl+S 保存，Ctrl+T 钉住，Enter 执行默认动作。再点一次当前工具即可取消选择，回到移动选区的状态。

实现要点：

- **数据模型**：标注是一组按屏幕坐标保存的矢量对象（矩形、椭圆、箭头、折线、文字、马赛克块）。调整选区不会移动已有的标注，输出时按选区裁剪。
- **渲染**：形状用 GDI+ 抗锯齿绘制。文字用与输入框相同的 GDI 字体渲染，保证输入时看到的就是最终效果。已提交的标注缓存成一个图层，只有正在画的对象实时重绘。
- **文字输入**：用系统自带的 EDIT 控件承载输入，天然支持输入法、光标、选中和粘贴。控件背景用截图在该位置的图像做画刷，所以输入时看上去就像直接写在截图上。输入完成后转成文字标注。
- **马赛克**：提交时从冻结的屏幕图像计算像素块（块大小为 10 逻辑像素），保存为一个小位图对象。
- **输出（拍平）**：从冻结图像裁出选区，按顺序画上全部标注，得到最终图像，供复制、保存和钉住使用。

#### 2.5.4 输出：复制与保存

- **复制**：
  - 剪贴板中同时写入两种格式：`PNG`（注册格式，Office、浏览器和设计软件优先读取）和 `CF_DIB`（微信、QQ、画图等使用）。其他格式由系统自动合成。
  - 剪贴板被其他程序占用时重试，每次间隔 20 ms，最多 10 次。
  - 完成后在选区位置显示 1 秒的“已复制”提示。
- **保存**：
  - 使用系统的“另存为”对话框（`IFileSaveDialog`，Win7 可用）。
  - 默认目录为配置项 `Save.Folder`，本次运行期间会记住上次使用的目录。默认文件名按模板生成（`VisPick_{date}_{time}`）。
  - 格式为 PNG（默认）、JPG 或 BMP，用 WIC 在后台线程编码写盘。
  - 保存后关闭浮层并提示保存路径，点击提示可以打开所在文件夹。

#### 2.5.5 参考图

**窗口实现**

- 每张参考图是一个独立的顶层窗口：样式为 `WS_POPUP`，扩展样式为 `WS_EX_LAYERED | WS_EX_TOOLWINDOW | WS_EX_TOPMOST`。它不出现在任务栏和 Alt+Tab 中，但可以获得焦点，以便接收快捷键。
- 用 `UpdateLayeredWindow` 加预乘 BGRA 位图渲染。一次调用就同时实现逐像素透明（阴影、虚线框）和整体不透明度；完全透明的像素会让鼠标点击穿过。

**缩放**

- 用 WIC 缩放器：缩小时用 Fant 插值（高质量），放大时默认用 Cubic 插值；配置 `Smooth=false` 时改用最近邻，适合像素级的 UI 参考图。

- 以光标为锚点缩放：`新位置 = 光标 − (光标 − 旧位置) × 新缩放 / 旧缩放`。
- 缩放范围为 10%–800%。渲染出的位图面积不超过虚拟桌面面积的 2 倍；32 位版另设更低的上限。

#### 2.5.6 GIF 录制

**录制界面**

- 录制框：在选区**外侧**画一圈 2 px 的红框，鼠标可以穿透。
- 工具条显示已录时长、停止和取消。
- 两者都设置为不被屏幕捕获（Win10 2004 及以上）。旧系统上的处理见 §2.2。

**编码流水线**

```
采集线程（按所选帧率）              编码线程池（N 个线程，帧之间互不依赖）     写出线程（按帧序）
BitBlt 选区 → 画鼠标指针 → 比较  ─▶  透明优化 → 生成调色板 → 像素映射 → LZW  ─▶  重新排序 → 计算延时 → 写入文件
  │ 画面无变化：只累加上一帧的时长，不提交
  │ 队列内存超出上限：本拍不抓，时长并入上一帧
```

- **采集**：
  - 默认使用 `SRCCOPY`。`[Advanced] capture_layered_gif=true` 可加入 `CAPTUREBLT`，录制日志记录实际选择。两条路径的物理显示性能和光标表现需实测。
  - 用高精度定时器按所选帧率抓帧。旧系统降级为 1 ms 精度的定时器。
  - 每一帧都和“上一个已提交的帧”比较，算出变化区域，只把变化区域（当前帧和上一帧对应的部分）提交给编码队列。
- **编码**：线程数 = CPU 核心数 − 2，限制在 1–6 之间。每一帧独立完成以下步骤：
  1. **透明优化**：变化区域内与上一帧相同的像素标为透明色。
  2. **调色板**：区域内的颜色不超过 255 种时，直接使用精确调色板，结果无损（界面类画面通常属于这种情况）。超过 255 种时，用 Wu 算法量化为 255 色；可选 Floyd–Steinberg 抖动。
  3. **映射与压缩**：借助 32K 颜色查找缓存把像素映射到调色板，再做 LZW 压缩。
- **写出**：
  - 按帧序号重新排序后写入 `%TEMP%\VisPick\rec_*.gif`。
  - 每帧的延时要等下一帧的时间戳到来后才能确定。GIF 的延时以 10 ms 为单位，因此 30 fps 时按 30/30/40 ms 循环，舍入误差带入下一帧，不会累积。
  - 生产录制的帧延时最短为 20 ms。过近的变化合并到下一次提交，避免播放器将 10 ms 重新解释为更长延时。
- **内存与背压**：采集和编码流水线的缓冲预算为 x64 256 MiB、x86 128 MiB。所选输出比例超出预算时，录制前降低比例并保留整个选区。运行中队列满时跳过本拍，将时长并入上一帧，丢帧数计入统计。
- **结束**：
  - 再按 Ctrl+2、点「停止」或到达五分钟时停止采集，等待编码完成后打开预览。
  - 点取消：不足 3 秒的录制直接丢弃，较长录制先打开预览供保存或确认放弃。录制期间 Esc 仍由前台程序接收。
- 锁屏时自动暂停录制。

#### 2.5.7 GIF 预览与保存

- 预览窗口是一个普通窗口，显示在任务栏中，避免被遗忘。标题为“GIF 预览 – VisPick”。
- 用 WIC 解码刚生成的文件，后台预取一帧，按帧延时循环播放。文件提交也在后台完成。内容超过屏幕的 80% 时按比例缩小显示。

- 进度条按 GIF 逐帧延时定位，支持点击和拖动跳转。
- 按钮与快捷键：
  - **保存…**：打开另存为对话框，默认目录为 `Save.Folder`，默认文件名为 `VisPick_{date}_{time}.gif`。与临时文件在同一磁盘时直接移动，跨盘时复制。
  - **放弃**：确认后删除临时文件。
  - **复制 GIF**：将原始动画送到剪贴板，支持按 GIF 文件粘贴。64 MiB 以内还提供 `image/gif` 数据。
  - 空格暂停或继续，Ctrl+S 保存，Ctrl+C 复制 GIF，Esc 放弃。

### 2.6 配置文件（INI）

**规则**

- 位置：默认为 exe 同目录下的 `VisPick.ini`。exe 目录不可写时，改用 `%APPDATA%\VisPick\VisPick.ini`。也可以用 `--config` 指定。
- 编码：UTF-8（有无 BOM 均可）和带 BOM 的 UTF-16。无 BOM 且 UTF-8 校验失败时尝试系统 ANSI 代码页。
- 首次运行时生成带注释的默认文件，**此后程序只读不写**，不会覆盖用户的修改和注释。
- 容错：
  - 键名不区分大小写。
  - 遇到未知的节或键时给出提示。
  - 首次启动时无效项使用默认值。运行中重载时，无效项和缺失项沿用上次有效值。
  - 整个文件无法解析时保留上次有效配置，并给出提示。文件被截断时延后重试一次。
- 保存后 1 秒内自动生效，包括重新注册热键、刷新现有参考图的样式。

### 2.7 工程与构建

- **构建系统**：使用 VS 自带的 CMake 3.29 和 Ninja。预设共四种：x64-Release、x86-Release、x64-Debug（开启 ASan）、x86-Debug。
- **编译选项**：`/std:c++20 /W4 /WX /permissive- /utf-8 /EHsc /MT /O2 /GL /Gy /guard:cf`。预定义宏：`_WIN32_WINNT=0x0601`、`WINVER=0x0601`、`UNICODE`、`NOMINMAX`、`WIN32_LEAN_AND_MEAN`。
- **链接选项**：`/LTCG /OPT:REF /OPT:ICF /SUBSYSTEM:WINDOWS /DELAYLOAD:shcore.dll`，并把 manifest 嵌入 exe。x86 另加 `/LARGEADDRESSAWARE /SAFESEH`，x64 另加 `/HIGHENTROPYVA`。
- **manifest**：
  - 声明支持 Win7/8/8.1/10/11（supportedOS）；
  - DPI 感知（见 §2.4）；
  - 通用控件 v6；
  - 支持长路径；
  - `asInvoker`（不请求管理员权限）。
- **`build.ps1` 一键构建**：
  1. 定位 VS2022 的 v143 工具集，并校验版本为 14.3x–14.4x；
  2. 构建 x64 和 x86 两个版本；
  3. 运行单元测试；
  4. 检查导入表：只允许依赖系统 DLL；不得依赖 VCRUNTIME、MSVCP、UCRT；不得静态导入 Win7 上不存在的 API；
  5. 输出到 `dist/`。
- **代码规范**：
  - 只用 RAII 管理资源，禁止裸 `new`/`delete` 和手工释放句柄；
  - 跨线程只通过消息和队列通信；
  - 每个模块都配单元测试；
  - 用 `/analyze` 做静态分析，不允许新增告警。
- **版本管理**：Git，主分支开发，每个阶段验收通过后打一个标签。

### 2.8 质量保障手段

- **单元测试（doctest）**：
  - INI 解析、热键解析、路径模板；
  - 选区几何（手柄、跨屏、负坐标）；
  - 收缩坐标换算、缩放锚点；
  - LZW 编码后再解码的往返校验；
  - 量化器：调色板不超过 255 色，精确调色板路径无损；
  - GIF 写出后用 WIC 解码，逐帧比对；
  - 延时舍入和误差传递、变化区域计算、马赛克。
- **自动化端到端测试**：用 VisPickTest.exe 驱动，见 §5.3。
- **性能埋点**：带 `--perf` 参数启动时，把关键耗时写入日志，包括热键到浮层的时间、每次重绘的耗时、编码吞吐量和丢帧数。
- **稳定性**：用浸泡测试脚本长时间运行，监控 GDI/USER 对象数、句柄数和内存。
- **崩溃处理**：发生未处理的异常时，用 dbghelp 在 exe 目录写入 minidump 并提示用户。正常运行时不会产生任何额外文件。

## 3 开发路径

### 3.1 阶段划分与依赖

```
P0 工程基线与技术验证
 └─▶ P1 常驻框架
      └─▶ P2 选区浮层（含基础截图：选区后可以直接复制）
           ├─▶ P3 截图编辑与保存 ──▶ P4 参考图 ──┐
           └─▶ P5 GIF 录制与预览（只依赖 P2）────┴─▶ P6 兼容性、稳定性与发布
```

单人开发时按 P0 → P1 → P2 → P3 → P4 → P5 → P6 的顺序进行。

| 阶段 | 版本号 | 结束时你能用到的东西 |
|---|---|---|
| P1 | v0.1 | 托盘常驻，热键和配置文件可用 |
| P2 | v0.2 | **已可日常使用**：Ctrl+1 选区后复制 |
| P3 | v0.3 | Ctrl+1 截图的全部功能：编辑、复制、保存 |
| P4 | v0.4 | Ctrl+3 参考图的全部功能 |
| P5 | v0.5 | Ctrl+2 录制 GIF、预览和保存 |
| P6 | v1.0 | 经过兼容性和稳定性验证的正式版 |

### 3.2 排序原则

1. **风险前置**：最大的四项不确定性在 P0 用原型实测，拿到数据后再开始做功能：Win7 兼容、DPI 坐标、超大画布的绘制性能、30 fps 下 GIF 的编码吞吐。
2. **尽早可用**：P2 结束时基础截图就能日常使用，之后每个阶段都在可用版本上叠加功能，你可以边用边反馈。
3. **先共用、后专用**：选区浮层是三种模式的共同入口，先把它做扎实。编辑器同时服务截图和参考图两种模式。
4. **按使用频率排序**：截图 → 参考图 → GIF。

### 3.3 每个阶段的工作流程

1. 实现功能，同时编写单元测试。
2. 运行自动化验收（E2E）并在本机手工检查，形成《阶段验收报告》：逐条列出验收标准和结果，附截图和实测数据。
3. 交付：x64 和 x86 两个 exe、验收报告、手工验收清单（给你用的操作步骤）、更新日志。
4. 你按清单验收。发现问题时修复，然后重新交付。
5. 验收通过后打版本标签，进入下一阶段。阶段内新增的需求统一记入待办，在后续阶段或 v1.1 中处理。

### 3.4 通用完成标准（每个阶段都必须满足）

- [ ] x64 和 x86 的 Release 版都能一键构建；`/W4` 零警告，`/analyze` 没有新增告警。
- [ ] 单元测试 100% 通过。用 Debug + ASan 跑完本阶段的 E2E 用例，没有内存错误。
- [ ] 导入表检查通过：只依赖系统 DLL，可以在 Win7 上加载。
- [ ] 本阶段的新功能在本机（双 4K，175% 缩放）上验证通过。
- [ ] 没有已知的崩溃。GDI/USER 对象不泄漏：同一操作重复 100 次后，对象数回到基线 ±5 以内。
- [ ] 新增的配置项、快捷键和已知问题都已写入文档。

## 5 测试环境与验收方法

### 5.1 环境矩阵

| 环境 | 用途 | 现状 |
|---|---|---|
| 本机：Win11 25H2 x64，2×4K@175% | 主要的开发与测试环境；可以临时切换 100%/125%/150%/200%、混合 DPI、副屏位置，覆盖 DPI 矩阵 | ✅ 已具备 |
| Windows 沙盒 | 纯净的 Win11 环境，用来验证程序确实没有依赖 | ⚠️ 未开启，需要管理员权限开启一次 |
| Hyper-V 虚拟机：Win10 22H2 x64/x86 | 兼容性测试 | ⚠️ Hyper-V 未开启；可以使用微软的评估版镜像 |
| Hyper-V 虚拟机：Win7 SP1 x64/x86（Win8.1 可选） | 旧系统兼容性测试 | ⚠️ 需要你提供镜像 |
| Windows on ARM 设备 | 验证 ARM 设备上的模拟运行 | 可选 |

### 5.2 需要你准备的资源

1. 在“启用或关闭 Windows 功能”中开启 **Windows 沙盒**和 **Hyper-V**。这需要管理员权限，并重启一次。
2. 提供 **Win7 SP1 安装镜像**（x86 和 x64），微软已经不再提供下载。如果没有镜像，Win7 只能做静态检查（编译期约束 + 导入表检查），实机验证改由你在旧设备上完成。
3. 如需在 ARM 设备上验证，需要一台 Windows on ARM 设备（可选）。

### 5.3 自动化验收工具 VisPickTest.exe

这个工具只在开发时使用，不随产品发布。

- **测试图样**：在指定的物理坐标上绘制带坐标编码的彩色图样，可以跨屏显示，也可以播放已知帧序列的动画。
- **输入模拟**：通过命令行和 `SendInput` 模拟热键、拖动和按键。
- **结果校验**：读取剪贴板、保存的文件、参考图窗口的位置和像素、GIF 解码后的各帧，与期望值逐像素比对。
- **报告**：每次运行生成一份 Markdown 报告，包含通过/失败、差异截图和耗时数据，作为阶段验收报告的附件。
- 运行时会接管鼠标和键盘（约几分钟），期间请勿操作。

## 6 风险与对策

| 风险 | 影响 | 对策 |
|---|---|---|
| 缺少 Win7 测试环境 | 无法在实机上验证旧系统 | 用编译期约束和导入表检查保证程序可以加载；请你提供镜像或旧设备做最终确认 |

| 30 fps 录制大区域时编码跟不上 | 丢帧 | 并行编码、只编码变化区域、合并相同帧；背压机制保证时长准确；必要时增加 DXGI 采集（由 AC0-7 决定）；提供缩放输出选项 |
| 超大画布绘制卡顿 | 体验差 | 只重绘脏矩形；在 P0 先实测验证（AC0-5） |
| 文字工具的输入法兼容问题 | 无法输入中文 | 用系统 EDIT 控件承载输入，天然支持输入法 |
| C++ 的内存和句柄错误 | 崩溃、泄漏 | RAII、ASan、`/analyze`、泄漏回归脚本、浸泡测试 |
| Ctrl+1/2 与其他软件冲突 | 热键由已注册它的应用接收 | 热键可配置；冲突时通知并重试 |
| 被杀毒软件或 SmartScreen 拦截 | 首次运行受阻 | 不加壳，带版本信息；有条件时做代码签名 |
| HDR 显示器上截图偏色 | 画面颜色不准 | v1 记为已知问题，后续可以加 DXGI 采集 |
| 32 位版的内存上限（2–4 GB） | 超大区域或参考图很多时内存不足 | x86 版限制编码队列和参考图的渲染尺寸，超限时给出提示 |

## 8 待确认问题

1. **参考图（Ctrl+3）也用“调整、编辑后再确认”吗？** 本方案默认是，同时提供 `Pin.Instant=true` 选项，恢复 SETUNA 的松手即贴。
2. **还需要其他编辑工具吗？** 比如直线、序号标注、荧光笔、实心矩形。默认不做，如果需要，可以在 P3 以很低的成本加入。
3. **高分屏上 GIF 按什么尺寸输出？** 按原始像素输出更清晰，但体积约为 100% 尺寸的 3 倍；缩回 100% 尺寸则体积小、略模糊。本方案默认按原始像素输出。
4. **发布两个 exe 可以吗？** 即 x64 推荐版加 x86 通用版。也可以只发布一个 x86 通用版。
5. **测试环境**：能否开启 Hyper-V 和 Windows 沙盒，并提供 Win7 镜像？
