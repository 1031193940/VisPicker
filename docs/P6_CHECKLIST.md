# P6 兼容性、稳定性与发布验收清单

本清单对应 [DESIGN.md 的 P6 与第 5 节](DESIGN.md)，记录执行方法和证据边界，不修改原验收标准。当前为开发验收清单，不能据此称 v1.0 已通过全部验收。已知实测见 [2026-11-06 报告](reports/P6-2026-11-06.md)。

状态统一使用：**通过**（注明具体范围）、**失败**、**未测**、**环境不具备资格**、**跳过**（明确决定）。代码存在、编译通过、模拟消息通过都不能替代相应实机步骤；旧版本结果也不能自动转为最终发布版本结果。

## 记录与执行约定

- 每轮记录源码提交、产品与测试程序 SHA-256、架构、Release/Debug、OS 版本与 build、GPU/驱动、会话类型、显示器物理矩形、刷新率、DPI、测试起止时间及原始日志。
- 桌面测试串行执行。自动化使用自有图样和窗口；人工剪贴板、显示设置和 Explorer 测试安排在独立测试会话，不混入正常工作。
- 性能数据必须同时报告环境资格。远程会话、未知显示路径、低于 50 Hz 的输出不用于本地物理显示性能验收；不要仅凭 `SESSIONNAME=Console` 判断本地环境。
- x86 程序在 Win11 x64 上运行只覆盖该组合，不等于 Win10 x86 或 Win7 x86 已通过。导入白名单证明的是已核对静态依赖，不证明旧系统可运行。
- 未测项保留原样，继续可以独立完成的构建、代码与测试工作，不设置阶段审批暂停。

## 可复跑的自动化入口

以下命令从仓库根目录执行。先完成构建；有窗口的程序逐个运行。`build.ps1` 的默认 CTest 不能代替所有独立桌面测试。

```powershell
.\build.ps1 -Architecture all -Configuration Release -Analyze
.\out\build\x64-Release\VisPickAppIntegration.exe .\out\build\x64-Release\VisPick.exe --idle-seconds 600 --output .\out\reports\p6-app-x64-final
.\out\build\x64-Release\VisPickOverlayTests.exe
.\out\build\x64-Release\VisPickEditorTests.exe .\out\reports\p6-editor-x64-final.json
.\out\build\x64-Release\VisPickOutputTests.exe
.\out\build\x64-Release\VisPickPinTests.exe
.\out\build\x64-Release\VisPickRecordingIntegration.exe --seconds 60 --width 1920 --height 1080 --output .\out\reports\p6-recording-x64-final
.\tests\e2e\RunSoak.ps1 -Seconds 28800 -IntervalSeconds 30 -Output .\out\reports\p6-soak-x64-8h
```

x86 使用 `out/build/x86-Release`；60 秒录制尺寸按 AC5-3 使用 1280×720。录制图样工具覆盖确定性 UI 图样，不替代真实视频内容的 720p 丢帧测试。`VisPickOutputTests` 使用独立窗口站剪贴板，不验证第三方应用粘贴。上述路径须使用新目录，保留失败日志，不覆盖成后续通过结果。

浏览器 GIF 冒烟使用 Node.js 22+。先运行默认 2 秒 `VisPickRecordingIntegration`，再把输出的 `automatic-saved.gif` 交给 `node tests/e2e/CheckBrowserGif.mjs <automatic-saved.gif> <新报告.json>`。结果记录三种已装浏览器的合成采样和版本，精确时序与人工清单中的其他图样仍单独验证。

## 浸泡测试的覆盖与口径

[Soak.cpp](../tests/e2e/Soak.cpp) 实际调用生产 `CaptureScreen`、`AnnotationModel`/`EditorRenderer`、WIC 编解码、`PinManager`、`Recorder`。每轮捕获自有 256×144 被动图样，校验截图像素；绘制矩形并校验 PNG 往返；创建/关闭贴图；录制 1 秒 GIF 并逐帧 WIC 解码。贴图关闭调用 `ProcessPending`，回收站设 0；录制完成后 `TakeResult` 和析构结束工作线程及录制工具条，再采资源数据。仅删除返回路径属于本测试 PID 的临时 GIF。

覆盖范围为生产组件生命周期。完整交互另行验证，包括全屏 Overlay、真实 IME、用户剪贴板、第三方粘贴和保存对话框。录制使用生产边框与工具条。产品与浸泡工具均不注册全局 Esc。

- 三轮暖机后取基线。资源释放后立即采样一次，最多空闲 2 秒后再次采样，暖机与测量使用同一时点。所有空闲样本的 GDI、USER、句柄、私有提交均须相对基线增长严格 `<5%`。保留每轮的即时样本、专用与总工作集，供诊断释放时序和换页波动。采样不修剪工作集。
- 基线包含持续存在的测试图样窗口及采样器。报告中的生命周期采样不等于进程退出后的零资源；字体/分配器有界缓存仍需趋势解释，不能把正增长写成“零内存增长”。
- 从固定起点以 `nextCycle += interval` 排程，记录最大间隔和相对计划的迟到。自动化允许 250 ms 调度误差，超过即失败。schema 7 分别记录编辑、贴图、录制和 GIF 校验结束后的私有提交。采集会话的锁定、断开与显示配置变更会中止并写入报告。
- 默认在暖机前启动同版本校验进程，每轮执行完整 WIC 解码与合成，验证帧数、尺寸和时长。校验失败或超时判该轮失败。常驻进程的资源门禁覆盖采集、编辑、贴图和录制，以及等待校验返回的开销。生产预览窗口的回归单独执行。
- `-DiagnoseMemory` 在同一进程中做 WIC 校验，`-DiagnoseIsolatedMemory` 使用独立校验进程。两个模式均记录每阶段的 `VirtualQuery` 私有提交分布与默认堆采样到 `memory.jsonl`。
- GIF WIC 时长对照首帧采集完成到停止的实际活动时间，绝对差值最多一个 10 ms GIF 时间单位；不再接受名义 1 秒的 ±10%。1 秒探针仍不等于 AC5-4 的 60 秒及 `<1%` 验收。
- `eight_hour_elapsed` 只有实际 elapsed ≥28800 秒才为 true。`eight_hour_passed` 还要求 `interval_seconds=30`、未开启诊断、完成且无错误、未取消、节奏与资源门禁通过。
- `physical_environment_eligible` 独立记录，功能/稳定性结果不自动变成合格物理显示性能数据。10 分钟、1 小时原子检查点只报告当时进度。

## 人工验收步骤

### 干净系统与常驻框架（AC6-1/2、P1）

1. 从未安装 VisPick/开发工具的干净快照启动，记录 OS build、位数和已有系统更新。只复制对应 exe 到可写目录，双击；检查同目录中文 ini、托盘图标、无需安装程序或额外运行库。下载文件的 SmartScreen 单独记录，不当作程序安装。
2. 亲自按 Ctrl+1 完成截图、Ctrl+3 完成贴图、Ctrl+2 开始/停止短录制；不是只发送 `WM_HOTKEY`。重复双击确认单实例，再用 `--screenshot` 确认转发。
3. 在测试目录验证只读目录回退及提示；显式 `--config` 创建/读取失败须报告原路径，不能静默换目录。改热键后 1 秒内生效；分别写未知键、`Ctrl+`、越界值、坏编码，确认行号、原因和旧值保持。
4. 测试会话中由另一程序占用 Ctrl+2，确认冲突项与其他热键；释放后恢复。实际重启 Explorer，确认托盘自动恢复。测试自启开关写入/删除后注销并登录确认行为，结束时恢复测试前设置。
5. 运行十分钟 idle 测试并保留实际 elapsed；再退出，确认窗口/线程/热键释放。不要以 30 秒探针代替十分钟。

### 跨屏选区、混合 DPI 与贴图（P2、P4）

1. 在每个布局显示带单像素边框、坐标色块的已知图样；跨屏框选，逐个拖八个手柄、移动选区、按方向键 1 px 与 Shift+方向键 10 px，比较尺寸标签与输出像素。
2. 单击普通窗口检查可见边界，Win10+ 要求 0 px 误差；单击桌面选择该显示器。对图样的已知坐标核对放大镜 RGB。
3. 生成贴图时与源位置逐像素重合；在不同 DPI 屏间来回拖动，核对 1:1 物理像素，不跳位、不缩放模糊。滚轮光标锚点误差 ≤1 px，范围 10%–800%。
4. 在 175% 下双击收缩为 88 物理像素；检查 80% 不透明度、蓝色虚线，拖动后还原锚点误差 0 px。Ctrl+滚轮改变透明度。
5. 根据 DESIGN 的 S01–S19 逐条执行并分别记录：拖动；方向键；Shift+方向键 50 px；双击收缩/还原；收缩态 Esc/Enter；Alt+上下 10%；Alt+Shift+上下 1%；数字 5–9；0；Alt+左右透明度 10%；Alt+Shift+左右 1%；R；Alt+H；Alt+V；Ctrl+C；Ctrl+X；Ctrl+V；Ctrl+S；Esc/Q。
6. 遍历右键菜单，鼠标穿透后从托盘恢复，关闭七张后只恢复最近五张。断开测试副屏、改变分辨率，核对离屏贴图回到可见区域；恢复原显示设置。

### 真实中文输入与文字一致性（AC3-2）

1. 在带彩色背景的截图选区启用文字，分别使用微软拼音及已安装的搜狗输入法，记录版本；真实键盘输入中文并从候选窗选词，不能用 `WM_SETTEXT` 代替。
2. 输入中英混排、标点、多行、Tab、足够长的自动换行段落，测试退格、选中替换、粘贴、候选窗方向键。分别测试 14/20/28 字号及至少 100%/175% DPI。
3. 去掉选区高亮与光标干扰，保留输入中截图；切工具/点外部/输出前提交后再截图，对照文字起点、行距、换行、Tab 位置和背景。另在输入中按 Esc，确认只提交文字，截图编辑会话仍在。
4. 三方字体缺失或回退单独记录。已完成的隐藏 EDIT 位图比较只证明原生控件绘制与提交的一致性，不能勾选本项真实 IME。

### 跨应用粘贴和保存（AC2-6、AC3-4/5、AC4-9）

1. 用含六种标注、细线、文字、马赛克与边缘色块的图样复制，依次在画图、Word、PowerPoint、微信、QQ、Chrome 可编辑/图片接收页面粘贴；记录目标版本、图片尺寸、方向、颜色、标注与裁剪。普通截图也单独检查 Enter/双击完成。
2. 微信/QQ 使用测试会话或文件传输助手的草稿，不向真实联系人发送；Chrome 使用本地或专用测试页面。无目标软件时标未测，不用自制剪贴板读取器替代。
3. 另存 PNG/JPG/BMP：默认目录/模板文件名正确；取消返回原编辑会话；保存后路径通知及打开文件夹可用。PNG 与复制内容逐像素一致；JPG 有损，不要求与源逐像素一致。
4. 对贴图执行复制、剪切、另存为、粘贴为新图；确认剪切复制成功后才关闭，透明/不透明图片和旋转翻转后的方向一致。

### GIF 全流程、播放器与边框（P5）

1. Ctrl+2 框选、调整区域，Enter/● 开始，Ctrl+2/■ 停止；暂停/继续、取消不残留本次临时文件。确认从真实全局热键进入的路由。
2. 录制带帧号/时间标记的图样和真实视频内容；WIC 检查输出中没有录制边框/工具条。Win10 2004+ 检查任意区域；更旧系统检查非全屏区域，并记录全屏限制。
3. 录满实际 60 秒自动停止，保存采集完成、停止时间、GIF delay 总和、采集/丢帧统计和进程内存峰值；按下面原始阈值判定。生产管线的预算字节不能当作进程内存峰值。
4. 用 Chrome、Edge、Firefox、Windows 照片、微信、QQ 分别播放同一 GIF，至少看三个循环；比较帧号顺序、色块、暂停保持、透明差分、总时长和节奏。WIC 回读成功不等于这六个播放器通过。
5. 停止到预览可见计时，检查循环、尺寸/时长/体积、保存到所选位置、放弃前确认。受系统版本限制无法安装某播放器时记录不适用原因，并保留对应平台可用播放器结果。
